# リマインダーのルールとテストケース（R-系）

- 基準時刻（now）: **2026-10-03(土) 12:00 JST**（固定。週の始まりは月曜）
- 関数: parser が reminder{raw} を返したあと、parseReminder(raw, now) を呼ぶ
- テストの入力は「メッセージ全文（先頭の / を含む）」とし、parser → parseReminder を通して検証する
- 結果: ok{content, remindAt（JST, 分精度）} または error{code}
- エラーコード: PAST / UNPARSEABLE / NO_CONTENT / NO_DATETIME / MULTIPLE / TOO_FAR

## 補完ルール
| 区分 | ルール |
|---|---|
| 日付のみ（明日、10/5、月曜） | 09:00 |
| 時刻のみ（15時、15:30） | 今日のその時刻。過ぎていれば明日 |
| 時間帯語のみ（朝・夕方・夜・今夜） | 朝 08:00 / 昼 12:00 / 夕方 17:00 / 夜・今夜 20:00。今日分、過ぎていれば明日 |
| 日付＋時間帯語（明日の朝） | その日の上記時刻 |
| 午前・午後なしの「H時」 | 6〜11時=午前、12〜23時=そのまま、1〜5時=午後（13〜17時）、0時・24時=午前0時 |
| 午前・午後あり | 明記に従う |
| N分後・N時間後 | 現在時刻＋N（秒は切り捨て） |
| N日後 | 日付＋N日。時刻指定がなければ 09:00 |
| 曜日のみ（月曜） | 今日より後で最も近いその曜日（今日が月曜なら来週） |
| 来週X曜 / 再来週X曜 | 来週（月〜日）/ 再来週のX曜日 |
| 今週X曜 | 今週内。過去なら PAST |
| 月日のみ（10/5） | 過ぎていれば翌年（1年以内なら可） |
| 月末 | 当月末日 09:00。過ぎていれば PAST |
| 「来月」だけ、「そのうち」など | UNPARSEABLE |
| 「今日」「今日の9時」など今日を明示して過去 | PAST |
| 日時表現が複数 | MULTIPLE |
| 現在から1年超先 | TOO_FAR |
| 内容が空 | NO_CONTENT |
| 日時表現なし | NO_DATETIME |
| 日時表現に解釈不能なものだけがある | UNPARSEABLE |

## fixtures の形式（test/fixtures/reminder-cases.json）
```json
[
  {"id":"R-01","input":"/歯医者 明日15時","expect":{"ok":true,"content":"歯医者","remindAt":"2026-10-04T15:00"}},
  {"id":"R-09","input":"/薬 今日の9時","expect":{"ok":false,"code":"PAST"}}
]
```
- parser-cases.json も同様に {"id","input","expect"} とする
- 整合性テスト: この md の表のID一覧・入力と fixtures が完全一致すること
