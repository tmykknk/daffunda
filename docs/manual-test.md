# 実機・ローカル確認手順（人間が実施）

実機でLINEの設定・配送を確認し、障害や競合はローカル統合テストで確認する。
エージェントは本番デプロイ・Secret操作・リモートD1操作を行わない。

## 準備

- [LINE設定](line-setup.md)と[デプロイ手順](deploy.md)のA/B0/B（更新はC）を完了する。
- 自分のテスト用グループで実施し、Push無料枠を確認する。日付・時刻はAsia/Tokyoで読む。
- 本文は下表のダミーだけを使う。実在のID・本文・トークン・署名・Worker URLを記録表、Issue、PR、チャットに貼らない。
- 許可グループ変更の確認を行う前に、旧グループの不要な予定を取り消す。開始済みの送信は巻き戻せない。
- `#N`は登録確認・一覧に出た内部IDを手元で読み、「リマインド削除 N」のNを置き換える。番号を固定値と決めつけない。

## LINE実機チェック

| 項目 | 操作（ダミー入力） | 期待 |
|---|---|---|
| 疎通 | `ヘルプ` | 使い方を1回返信。LINEの自動応答による重複がない |
| 買い物 | `+テスト品目A テスト品目B` → `リスト` | 2件追加され、一覧に両方ある |
| 重複 | `+テスト品目A` | 登録済み。重複が増えない |
| かな照合 | `+テストみるく` → `-テストミルク` | かな違いでも削除成功 |
| 削除 | `-テスト品目A`を2回 | 1回目は削除、2回目は見つからない |
| 正規化 | `＋テスト品目C`、`りすと` | 全角プラスでも追加され、別名で一覧表示 |
| 無視 | `テスト雑談`、スタンプ、画像 | 返信も業務登録もない |
| 予約語/使用例 | `+リスト`、`+`、`リマインド削除 abc` | 禁止名・使用例を案内し、登録・取消しない |
| 品目上限 | ダミー品目21個を1メッセージで送る | 上限エラー。一部だけ追加しない |
| 名前上限 | `+`に「あ」51個を続ける | 上限エラー |
| 登録確認 | `/テスト予定 明日15時` | 内容・明日15:00 JST・内部ID・取消コマンドを返信 |
| 日付補完 | `/テスト日付 明日` | 明日09:00 JSTで登録 |
| 一覧 | `リマインド` | 登録した予定が日時順で表示され、IDは登録確認と同じ |
| 日時エラー | `/テスト 昨日`、`/テスト`、`/明日15時` | 過去・日時なし・内容なしを案内。予定は増えない |
| 複数日時 | `/テスト 明日15時 明後日` | 日時を1つにするよう案内。登録しない |
| 数値拒否 | `/テスト 1.5時間後`、`/テスト -30分後`、`/テスト 0003/5`、`/テスト ２０２７／３／００５` | 部分解釈して登録せず、日時解釈エラー |
| 正常な桁数 | `/テスト日付 03/05` | 3月5日の09:00として、必要なら翌年へ補完。表示を確認して取消 |
| 取消 | 登録確認・一覧の取消ボタンと、登録されたIDを指定して`リマインド削除 N` | 取消成功し一覧から消える。文字コマンドの再取消は見つからない、ボタン再操作は取消済み、送信済みのボタンは送信済みと案内 |
| ID維持 | すべてのダミー予定を取消後、新しいダミー予定を登録 | 空の一覧でもIDはリセットされず、旧IDの取消で新予定は消えない |
| 発火 | `/テスト発火 2分後` | 登録確認の時刻を確認。期限到来後の毎分Cronで`⏰ リマインド: テスト発火`が届き、未送信一覧から消える |
| 発火前取消 | 別の2分後予定を登録し、期限前に取消 | Pushが来ない（送信開始済みの場合は取消不可逆性に注意） |
| 長い一覧（任意） | 1メッセージの上限内でダミー品目を複数回追加し一覧表示 | 上限内へ省略し「…他N件」を表示。省略されたDB内容は残る |

Pushの到着時刻にはCronと配送の遅延がある。`sent`はLINE APIの受理で、端末への到達保証ではない。発火しない場合はトークン・許可グループ・Cron設定・Push無料枠を手元で確認し、固定エラーコードを見る。メッセージ本文や秘密を診断ログへ追加しない。

## 許可グループ・設定変更（自分の検証環境）

1. 未設定/仮値の間は、Webhookの業務更新とCron送信が止まることを確認する。設定操作は[運用手順](deploy.md)に従い人間が行う。
2. 許可グループでは`ヘルプ`へ返信し、別グループ・1対1では返信しない。拒否ログはtypeとIDだけで本文・署名・Secretを含まない。ログのIDは外へ持ち出さない。
3. 許可IDを変える前に、旧グループの不要な予定を取消する。許可外で保持された予定は新グループへ宛先変更されない。
4. 保持の挙動を検証する場合は専用のダミー予定だけを使う。再許可すると期限到来予定は送信対象になり得る。初回claimから24時間の再試行期限は延長されない。

## ローカルで確認する項目

実機で障害・同時再送・429を意図的に起こす必要はない。実際のLINEへの負荷や無料枠消費を避け、LINEクライアントをモックにした既存テストで確認する。

```sh
mise exec -- pnpm exec vitest run test/repo.test.ts test/line.test.ts
TZ=UTC mise exec -- pnpm check
TZ=Asia/Tokyo mise exec -- pnpm check
```

- [署名の独立照合](deploy.md)のB0: 正しい署名・空eventsは200、本文改変・空白追加・署名欠落は401。DB/LINE API無操作を確認する。
- D1統合テスト: 同時再送、業務SQL途中失敗の全体ロールバック、再送後の1登録・1返信、処理済みイベントの再実行拒否。
- Cron統合テスト: 同時claim、3失敗、429の安全ログ、5分境界、24時間境界、取消との競合、旧claim完了、受理後DB障害と同じキーの409復旧。
- 許可変更: 未設定・仮値・他グループの予定を送らず保持、同時Cron・滞留復旧・再許可でも宛先/本文/retry_keyを維持。
- 日時: [固定JSTケース](reminder-cases.md)と追加fixtureで小数・負数・月/日桁数、翌年/閏年・日付跨ぎを確認する。
- 文字数: Reply/PushのUTF-16上限とサロゲートペア・省略・DB内容保持は自動テストで境界を確認する。
- 移行: 初期スキーマから現行へ更新して既存予定・処理済みイベントを保持。コードよりマイグレーションを先に適用する。

ローカルの秘密ファイルがIDガードを止める場合、値を出力・変更せず秘密ファイルのないcheckoutで検査する。検査設定やfixture期待値は緩めない。

## 確認記録と後片付け

| 項目 | 結果の記録 |
|---|---|
| 対象リビジョン | コミットSHA |
| 自動検査 | UTC/JSTの成否・CIリンク・pending件数（0件が完了条件） |
| LINE実機 | 上記各項目のOK/NG/未実施と、NGの固定コード・再現手順（ダミーのみ） |
| 残課題 | 配送保証・無料枠・設定など[設計判断](decisions.md)へ照合 |
| 後片付け | 作成したダミー品目と未送信予定を削除/取消。Secretとログを外へ転記しない |

[独立タスクI1](tasks.md)の取消ボタンも、登録確認・一覧からの操作、同じボタンの再操作、送信済みの古いボタン、別グループからの操作、11件以上のページ送りを確認する。実機確認を実施していない場合は「未実施」と記録し、成功扱いにしない。
